# 生成产物补录恢复

> 2026-09-13：已实现；属于既有 Run/历史维护，不启动 Phase 2/3。

## 用途与边界

请求超时或平台未确认提供方状态时，上游可能已经产出文件。仅把找回的图片写到节点 `lastAssets` 会有图无历史；补录恢复把**已有平台资产**登记为独立可追溯历史。

- 原 Run、失败错误、原时间和原输出列表保持不变。
- 新记录 `status=succeeded` 仅表示**恢复登记成功**，不是原请求成功，也不是重新生成；`recovery` 元数据和 UI“补录恢复”标识不可省略。
- `parentRunId` 和 `recovery.sourceRunId` 指向原 Run，原输入快照/输入资产/能力版本从原记录复制，新的操作者和补录时间单独记录；`providerRunId=null`，不虚构提供方任务或生成耗时。
- 不调用模型、不重新生成、不写 graph、不增加 canonical revision、不替换当前或已批准选择；候选只追加。新候选组只有在节点已经显示该资产时才标记当前；已有组保留选择/批准。
- 来源说明可由系统记录自动起草并由操作者核对确认，不是系统验证上游生成成功的证据。不能为了让历史出现，把任意参考图片归因为生成产物。

## 人工操作

1. 先正常取得编辑权。
2. 在生成卡片下方或顶部“生成历史”流水中，点击“补录恢复”。
3. 选择原失败/取消/待核对 Run，系统优先查找当前产物并自动填写原因、来源与关联依据；核对后即可确认，无需重写。只有找不到足够关联记录时才手动补充。可修改自动说明；切换 Run/资产会重新查找，迟到的请求不会覆盖手动编辑。
4. 确认后，恢复产物进入节点生成历史；顶部流水保存原失败与新恢复记录。恢复标记可查看原 Run 和依据，顶部流水可展开详细来源和操作者。

支持图片、视频、音频；暂不支持补录文字。需先使用既有受控上传接口将外部文件导入为平台资产，本功能本身不下载上游结果或接受任意文件路径。卡片入口列出最近 20 条可恢复原记录，顶部流水按原有历史列表访问其他记录。

## API

实时 Action Registry：`run.recover`。接口为 `POST /api/runs/:id/recover`：

只读 `run.recovery_suggestion`：`GET /api/runs/:id/recovery-suggestion?assetId=...` 返回 `{assetId,reason,evidence,hint}`，无需租约，不调用 provider、不写业务数据。省略 assetId 时取原节点当前产物；原因来自原状态与错误。依据来自存在的资产文件、当前产物关系、匹配的 provider 任务 ID 或同时包含 Run/asset ID 的节点备注。备注按已有陈述引用；仅当前节点关系不会声称同次上游生成已验证。只有资产归属、没有额外关联时 evidence 留空并提示用户填写。已补录的组合复用原说明以保持幂等。提交仍要求完整原因/依据及有效写入证明。

```json
{
  "leaseToken": "当前 token",
  "leaseEpoch": 1,
  "expectedRevision": 10,
  "assetId": "已有平台产物 ID",
  "reason": "原请求超时，后来找回上游输出",
  "evidence": "提供方任务 ID、原输出文件名及找回经过等关联依据"
}
```

返回 `{run,replay}`。操作者从有效租约推导，不能通过 body 冒充其他 actor。不接受活跃/成功 Run、恢复记录或无节点 Run；原节点必须仍存在。资产文件必须存在，归属同画布及同节点（未绑定节点的同画布资产允许显式补录），且不能是原输入参考素材；Codex 图像能力和 TTS 还校验图片/音频类型。ComfyUI 允许其实际平台媒体类型，由操作者核对其与原工作流输出的关联。已登记为其他成功 Run 输出的资产不能重复归因。

原因限 2000 字符、来源说明限 4000 字符，均不可为空。交接中禁止新补录。所有数据库写入与租约/revision 检查在同一 SQLite 事务内执行；本地恢复请求串行处理。确定性幂等身份为原 Run + assetId；相同原因/依据重试返回原记录，不增加候选或重置选择，修改已登记依据的重放返回 `IDEMPOTENCY_CONFLICT`。不允许对恢复记录调用 `retry`，若要重新生成应重试原 Run。

`GET /api/runs?canvasId=...&nodeId=...&status=succeeded&includeRecoverable=true` 附带最近 20 条 `recoverableRuns` 的最小来源信息，使卡片保持一次历史请求；成功历史分页不受失败记录挤占。历史/lineage/get 保留 `recovery` 字段。

## 持久化与验证

`generation_runs` 增加 nullable `simple-json` 列 `recovery`；现有记录为 null，按既有 TypeORM synchronize 启动迁移，不改写旧 Run。恢复记录为终态，启动时 queued/running 核对不会把它改成待处理。

后端 21 suites / 169 tests 通过，含 12 项 SQLite/HTTP 恢复测试：失败不变、候选/双向 lineage、串行和同时幂等重放、来源改写拒绝、批准/当前选择保留、lease/revision 拒绝、资产归属/输入引用/媒体类型拒绝、缺失文件、活跃/成功来源与交接拒绝，以及候选失败回滚。后端编译与前端生产构建通过。

本功能不自动补齐已有业务画布历史，不从备注猜测批量写入；用户需要确认产物关联依据后显式登记。

自动查找新增 3 项测试覆盖当前产物/备注只读发现、缺失关联手填、跨画布拒绝、任务 ID 匹配与已补录说明复用。3100 重启健康；真实 D03 Run/图片接口及 Chrome 弹窗已验证原因与依据自动填入，未提交业务补录。
