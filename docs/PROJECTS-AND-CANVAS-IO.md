# 项目管理与画布输入、工作、输出方案

> 状态：P1–P4 第一版已实现并验收。
> 日期：2026-09-14。
> 本次授权范围：详细设计及业务功能实施（2026-09-14 已授权）。
> 两项核心需求：增加项目机制；明确画布输入、工作、输出三个区域及快照流通机制。

## 1. 背景与目标

短视频制作拆成多张画布后，需要解决两类问题：项目把相关画布组织起来；画布输入输出把素材的流通和来源表达清楚。

例如“许明短片”项目包含人物设定、剧本、配音、镜头制作等画布。镜头制作画布可以引入人物设定画布当时的输出，也可以引入项目外的风格参考画布。引入后素材属于镜头制作画布，上游变化不影响它，用户主动更新才获得新的内容。

项目不是资源权限边界，也不是执行单元。画布仍是独立的创作、资源存储和控制权单元。

## 2. 已确认规则与本方案实施建议

### 2.1 已确认的产品规则

1. 侧边栏增加“项目”，支持新建项目、加入已有画布、在项目内新建画布。
2. 全局画布管理继续展示所有画布，并展示所属项目。
3. 项目记录自己关联的画布；同一画布可加入多个项目，不要求先移出其他项目。画布内容不保存项目归属。
4. 项目内还有画布时，项目不能删除。移出项目不删除画布。
5. 每张画布具有输入、工作、输出三个区域，可以为空。
6. 本地文本、音频、图片、视频文件导入时，复制到当前画布范围内。
7. 可以引入任意其他画布，不受项目归属限制。
8. 引入画布时，获取其此时输出内容的快照，存入当前画布输入区。
9. 上游后续变化不自动改变下游输入；用户点击更新才更新输入。
10. 项目归属变更不要求解除素材来源关系，不影响输入、工作和输出。

11. 项目没有输入区；项目可以选择关联画布的输出保存为项目产出快照，用于最终成果浏览。项目产出不能被画布或其他项目引用。

这组规则替代早期讨论中的单项目归属、迁移限制、同项目引用及切断关联限制。

### 2.2 本方案给出的具体实施建议

以下是为落地明确的默认行为，区别于用户直接提出的规则：

- 输出由用户明确发布，固定具体内容，不自动跟随节点最新结果。
- 默认整组引入来源画布的当前输出；第一版不增加单项订阅和筛选同步规则。
- 每次更新生成新的输入快照版本，旧版保留并可回退。
- 更新前展示整组差异；类型变化、删除等使现有连线失效时，阻止提交并说明处理方法。
- 第一版禁止引入自身；允许 A、B 相互引入已经存在的快照，因为没有自动递归执行。
- 输入输出面板位于工作区两侧，可折叠；工作区仍使用现有 React Flow。
- 第一版文本文件支持 UTF-8 的 txt、md、json；其他编码明确报错，文档提取、OCR、语音转写另行立项。

## 3. 范围与非目标

本次范围包含项目管理、三区域界面、通用文件导入、输出发布、跨画布输入快照、主动更新、历史来源、人工与 Agent 一致接口，以及兼容迁移。

不包含自动执行整张画布、项目级批量调度、自动更新或重跑下游、Shot Plan、时间轴、剪辑与最终成片导出。此需求不是恢复 AI-NATIVE-CANVAS.md 中暂不实施的 Phase 2/3。

第一版不做项目层级、共享项目资产库、磁盘文件去重、实时跨画布连线。项目关系总览可在核心功能验收后另做，不阻塞本次交付。

## 4. 项目机制

### 4.1 界面与路由

- `/projects`：项目列表，显示名称、说明、画布数量、更新时间，支持新建和重命名。
- `/projects/:id`：项目详情，显示项目信息与画布列表，提供“加入已有画布”“新建画布”“移出项目”。
- `/canvas`：全部画布，卡片显示项目名称或“未归属项目”，支持全部、未归属、指定项目筛选。
- `/canvas/:id`：同一画布编辑器，展示输入、工作、输出三个区域；项目关联标签在全局画布列表展示。项目页打开画布不创建副本。

“加入已有画布”展示尚未加入当前项目的任意画布，包含其他项目已关联的画布。多个项目打开的是同一画布，编辑共享生效。

### 4.2 关联与并发

使用 ProjectCanvas 关联表，(projectId, canvasId) 唯一；不在 CanvasDoc 保存 projectId。关联增删修改项目 revision，不获取画布 lease，也不增加画布 revision。全局列表通过关联表查询多个项目标签。

项目内新建画布后自动关联。项目删除在事务中检查关联数量，非空拒绝。删除画布在事务中清理所有项目关联，项目产出独立副本保留。关联操作校验画布/项目存在，并用项目 expectedRevision 防止并发覆盖。

### 4.3 项目产出区

项目详情包含画布集合与产出区，没有输入区和工作区。用户从当前关联画布选择具体输出项，可跨多张画布组合、命名、排序、添加说明。提交时固定来源输出版本、复制文字及媒体文件到项目自己的资源分区，形成不可变快照版本。

来源重跑、撤下输出、被移出项目或删除，都不改变已有成果。用户重新收集或替换时保存完整新版本，旧版可浏览和回退。不在来源被移出后自动拉取它的新版；重新收集只允许当前关联画布。

项目产出仅供预览、下载和最终成果浏览，不出现在画布输入来源列表，不提供可引用的项目输出接口，不隐含剪辑或自动合成。删除空项目时清理项目自己的成果副本，不删除任何画布。项目资源占用独立统计。

## 5. 三个区域的职责

| 区域 | 内容 | 主要操作 |
|---|---|---|
| 输入区 | 本地导入文件、其他画布输出快照、输入组历史和用途备注 | 导入、引入画布、预览、加入工作区、检查更新、更新、回退、移除 |
| 工作区 | 现有生成节点、类型化连线、候选和运行状态 | 编排、生成、选择候选、查看历史、设为输出 |
| 输出区 | 明确发布的文字或媒体成果及其名称、说明、顺序 | 发布、替换、重命名、排序、预览、下载、撤下 |

区域是正式领域状态，不由节点坐标推断。面板折叠、宽度、选择和 viewport 是本地展示状态，不增加 revision。

输入不是自动运行参数。“加入工作区”创建输入适配节点，再用现有 typed handles 连接到工作节点。图上适配节点引用 inputGroupId/itemKey，从当前快照解析本地资源；不把外部 assetId 直接塞入运行参数。

输出区不重复摆放全部生成历史。用户从节点当前内容或历史候选选择“设为输出”，填写名称与说明，固定该次内容。文字可以选择全文、正向或负向部分，每部分作为独立 text 输出项。

输入素材可以设为输出，用于整理参考素材的画布；仍必须显式发布。新成功候选和候选切换都不会自动替换已发布输出。

## 6. 输出发布与版本

每张画布维护 outputsVersion，只在输出列表发生变化时递增，不与 canvas revision 混用。移动工作节点、修改输入或重跑不会使输出版本变化。

输出项有稳定 outputId、名称、类型、说明、排序，以及固定内容的本地 assetId。替换同一输出保留 outputId；撤下后再次新建使用新 outputId，防止按名称错误匹配。

发布、替换、撤下均经 lease/revision/日志保护。发布文字时把完整文字物化成 text Asset；媒体可以引用当前画布已有不可变 Asset，不必在同画布再复制文件。任何已发布或历史版本引用的 Asset 都不得被节点清理删除。

输出每次变化形成不可变 manifest，记录版本、操作者、时间、输出项、源 nodeId/runId 和内容摘要。正在生成、失败且无产物的节点不能发布。现有批准保护仍有效；本次不把“发布输出”等同于“批准候选”。

## 7. 输入快照与主动更新

### 7.1 本地文件

选择文件 → 通用平台上传 → 校验类型、大小和文件内容 → 保存原文件副本 → 创建输入组与初始快照。

本地导入不要求 ComfyUI 在线，不加载生成 Provider，不自动转码。原文件保持字节一致；预览或 Provider 需要转换时使用派生文件，并记录转换关系。文件名与 MIME 只是辅助信息，必须结合内容校验。

一次选择多文件形成一个本地输入组。第一版本地组不监视原文件路径，也没有自动更新；重新选择文件可创建新组。浏览器上传不是后端任意路径读取。

### 7.2 引入其他画布

1. 选择任意其他画布，展示项目标签、输出列表和预览。
2. 读取并固定来源的最新 outputsVersion 与不可变 manifest。
3. 若没有输出，提示先去来源画布发布，不能把工作区候选默认为输出。
4. 将 manifest 内全部文件逐一复制到目标画布输入分区，文字也复制完整内容。
5. 全部复制与校验成功后，原子创建输入组、快照和本地 Asset 记录，增加目标画布 revision。
6. 输入区展示来源画布名称、引入时间、输出版本、内容、用途备注和“打开来源”。

同一来源可以多次引入，形成不同输入组，允许不同用途或固定不同版本。sourceCanvasId/sourceAssetId 仅用于溯源和更新，运行只使用目标画布的本地 Asset。

### 7.3 检查与更新

“检查更新”是只读操作：比较保存的 sourceOutputsVersion 与当前来源版本。仅在输入面板展开时低频检查，或由用户点击检查；不高频拉取整张上游图。

“更新输入”先固定最新 manifest，按稳定 outputId 比较新增、替换、移除、类型、名称和顺序变化。名称变化不改变内容身份。无变化时返回 no-op，不增加 revision 或重复复制。

用户确认后创建完整新快照，成功才切换 activeSnapshotId。可以复用本画布已有且校验一致的不可变文件，但每版 manifest 完整独立。更新失败、来源消失、revision 冲突、lease 丢失、磁盘不足都保持旧版生效。

预览与提交之间来源输出版本发生变化时，拒绝本次提交，要求重新预览；开始复制后固定单一 manifest，不把多个版本混在一组。

### 7.4 工作区绑定与回退

适配节点以 inputGroupId + itemKey 绑定输入项；画布来源的 itemKey 使用稳定 outputId，本地项使用独立 UUID。更新后同身份、同类型项解析到新版内容，现有连线保持；新增项只进入输入面板，不自动连线。

若新版移除已绑定项或改变其类型，提交前返回受影响节点/连线列表，要求先解除使用或保留旧快照。第一版不静默删节点、断线或让连线悬空。仍被提示词稳定引用的项也遵守现有 IMAGE_REFERENCE_IN_USE 等保护。

回退到旧快照同样需要 lease/revision，并做绑定校验；回退不删除新版本。移除整个输入组前必须先解除活动工作区绑定，但历史 Run/Checkpoint 引用的内容仍保留。

输入更新只影响未来提交。正在执行的 Run 使用提交时已冻结的 inputAssetIds/inputSnapshot；成功回调和历史结果不随 activeSnapshotId 改写，不自动生成新输出。

## 8. 来源、删除与资源生命周期

来源关系保存来源名称快照、canvasId、outputsVersion、outputId、原 assetId、nodeId/runId、引入时间及内容 hash。当前来源名称可以另外展示，但不覆盖历史名称。

来源被删除后，输入显示“来源已删除，无法更新”，已有快照、预览、下载、工作区运行仍可使用。来源输出被撤下后，旧输入仍可用；主动更新会展示移除差异。

项目删除不清理画布资源；项目关联变更不改变资源分区。删除目标画布时仅清理它自己的资源和状态，不能追随 sourceCanvasId 清理上游或其他画布。

资源保护集合扩展为：当前图、输入所有保留快照、输出所有保留版本、Checkpoint、Run 输入输出及既有批准资产。删除节点、清理候选均必须使用统一引用检查。第一版不提供版本文件批量清理，历史保留增加的占用计入画布资产大小。

源读取/复制需要临时读取保护：固定 manifest 并登记短期文件 pin；画布删除或 GC 不得在复制期间移除被 pin 的源文件。完成、失败、过期时释放。实现时使用统一资产引用/pin 服务，不靠 UI 保证。

## 9. 数据模型与实际存储

以下为逻辑模型。实际实现使用 Project / ProjectCanvas / ProjectReceipt 三张新表；画布输入组、快照与输出历史一起存入 CanvasDoc.io（nullable simple-json，schemaVersion=1），Checkpoint 同样增加 nullable io_state。旧记录为空时按空 IO 读取。manifest 的项目名、来源名和内容是历史快照，不依赖关联表实时解析。

| 实体/扩展 | 关键字段与约束 |
|---|---|
| Project | id、name、description、revision、成果快照历史、activeResultId、createdAt、updatedAt |
| ProjectCanvas | projectId、canvasId；组合唯一；关联不进入画布内容 |
| CanvasInputGroup | id、canvasId、sourceType=file/canvas、sourceCanvasId nullable、sourceCanvasName、name、note、activeSnapshotId |
| CanvasInputSnapshot | id、groupId、sequence、sourceOutputsVersion nullable、items manifest、createdAt、actor；不可变 |
| SnapshotItem | itemKey、localAssetId、kind、name、note、hash、sourceOutputId/sourceAssetId/sourceNodeId/sourceRunId nullable |
| CanvasOutputVersion | id、canvasId、version、items manifest、createdAt、actor；canvasId/version 唯一 |
| OutputItem | outputId、assetId、kind、name、description、order、sourceNodeId/sourceRunId、textPart nullable |
| Asset 扩展 | kind 增加 text；source 增加 import；字节 hash；来源映射优先在 manifest 保存 |
| CanvasCheckpoint 扩展 | 保存输入组与活动快照选择、输出 manifest；历史 Checkpoint 缺字段按旧 schema 处理 |
| GenerationRun 扩展 | 输入快照记录 inputGroupId/snapshotId/itemKey/localAssetId 和文字实际值，保留现有 Run 字段 |

文件建议放在 `data/assets/<canvasId>/input/`；由 Asset.relPath 定位，文件名仍使用唯一 assetId，用户文件名作为元数据。历史版本通过 manifest 引用不可变文件，不覆盖同一路径。

输入输出状态不混入 React Flow nodes/edges。agent-view 一次性返回图、输入组、当前快照、输出 manifest、项目信息与可用动作。关系查询是历史来源关系，不解释为实时执行 DAG。

## 10. 命令、API 与事务

### 10.1 已实现入口

| 能力 | API |
|---|---|
| 项目列表/创建/详情/删除 | GET/POST `/api/projects`；GET/DELETE `/api/projects/:id` |
| 项目编辑、关联、新建画布、成果收集/回退 | POST `/api/projects/:id/command` |
| 画布输入、活动快照、输出及全部历史 | GET `/api/canvas/:id/io`；agent-view 的 canvas.io 同样返回 |
| 本地文件导入 | POST `/api/canvas/:id/io/files`，multipart files + lease proof |
| 来源更新差异 | GET `/api/canvas/:id/io/inputs/:groupId/update-preview` |
| 画布输入/输出语义写入 | POST `/api/canvas/:id/io/command` |

项目命令体包含 expectedRevision、idempotencyKey、command、payload，command 为 edit、canvas.add/remove/create、results.capture/restore。项目删除需要 expectedRevision。画布命令体包含 leaseToken、leaseEpoch、expectedRevision、idempotencyKey、actorType/actorId、command、payload；command 为 input.capture/update/restore/remove/edit/bind 或 output.publish/replace/edit/remove/reorder。本地文件导入最多 30 个，单文件最多 256 MB，UTF-8 文本最多 5 MB。实际字段与实时 schema 见 GET `/api/actions`；操作示例见仓库 Skill 的 references/projects-io.md。

读来源不要求取得来源画布写 lease。所有改变目标画布状态的命令要求目标 lease/epoch/expectedRevision、actor 与幂等键；输入复制与图操作共享应用服务，不在 Controller 或 React onClick 中各写一套业务规则。

### 10.2 文件与数据库提交

文件系统与 SQLite 不能构成同一个事务，采用“暂存并校验 → 再检查租约/revision → 提交数据库 → 回收暂存”的流程：

1. 固定来源 manifest，登记读取 pin；先校验目标写入资格。
2. 文件复制至受控暂存位置，校验长度/hash；不暴露半完成输入。
3. 提交前重新检查目标 lease 与 revision，将不可变文件就位。
4. SQLite 事务提交 Asset 行、manifest、活动版本、Canvas revision、日志、幂等回执。
5. 数据库失败时新文件成为待回收孤立文件；旧活动状态不变。启动时重试回收。
6. 相同幂等键重放返回原结果；同键不同请求报冲突。提交成功但响应丢失不得重复复制/增版。

撤销与恢复也需要覆盖 IO 状态；不能只撤销图而留下已变化的输入。恢复旧 Checkpoint 不回退项目归属；历史输出恢复发布成新的 outputsVersion，避免版本号倒退。历史 Checkpoint 没有 IO 字段时保留当前 IO，只恢复旧图，并明确显示兼容行为。

### 10.3 错误与授权

复用 CANVAS_LOCKED、LEASE_EXPIRED、STALE_LEASE、REVISION_CONFLICT、IDEMPOTENCY_CONFLICT。新增 PROJECT_NOT_EMPTY、CANVAS_NOT_IN_PROJECT、SOURCE_VERSION_CHANGED、SOURCE_HAS_NO_OUTPUTS、SOURCE_COPY_IN_PROGRESS、INPUT_ITEM_IN_USE、INPUT_KIND_CHANGED 等结构化错误；无单项目归属冲突。

删除画布、历史清理、覆盖恢复与批准产物替换继续遵守现有高影响操作合同。普通导入、引入和可回退更新不因跨项目来源额外增加授权步骤。

## 11. 当前架构与改造位置

- `backend/src/canvas/` 已有 lease、revision、语义 operations、日志和 Checkpoint，扩展 IO 命令与 agent-view。
- `backend/src/assets/` 已按画布分区管理媒体，增加 text、通用文件副本、引用检查、暂存回收和读取 pin。

| 阶段 | 内容 | 当前状态 |

### P1：项目管理

1. Project / ProjectCanvas 实体、项目 CRUD、关联、事务与并发约束。
2. 加入/移出项目 API 和 Registry；画布列表查询返回 projects 标签。

验收：同一画布两处展示一致；同一画布可加入多个项目，移出一个不影响其他项目；非空删除被拒绝；并发加入/删除没有孤立归属；AI 占用不阻止项目关联操作，画布内容操作仍遵守控制权；重启归属保留。

### P2：三区域与平台 IO

1. IO 实体、schema、不可变 manifest、text Asset、暂存与引用服务。
2. 本地文件导入 API、输入适配节点与实际运行输入解析。
3. 明确发布/替换/撤下输出，输出版本及保护集合。
4. 三区域面板、预览、命名、备注、下载与工作区连接。
5. agent-view 与 Registry 暴露 IO；Checkpoint 保存 IO。

验收：四类文件导入副本可在原文件移除后使用；原文件 hash 一致；Provider 离线也能导入；文字完整不截断；类型不匹配被拒绝；节点重跑和候选切换不改变已发布输出；面板折叠不增 revision；节点清理不能损坏输出和历史输入。

### P3：跨画布快照与更新

1. 来源选择、固定输出版本、读取 pin、整组文件复制与来源映射。
2. 更新检查、差异预览、原子提交、幂等与无变化 no-op。
3. 稳定项绑定、移除/类型变化保护、输入旧版查看与回退。
4. 项目产出选择、独立文件副本、快照历史、预览下载与回退；只允许收集关联画布输出，拒绝项目作为引用来源。
5. 来源删除提示、跨项目自由引入和项目关联变更兼容。

验收：不同项目、项目外来源均能引入；A 改动后 B 输入不变；主动更新后 B 才变化；复制期间上游发布得到单一版本；来源删除后 B 仍能预览和运行；更新失败/租约丢失保持旧版；双向快照引用没有递归调用；新增不自动连线，删除使用中项不静默破图。

### P4：完整验证与交付

1. 旧画布保持原图与历史，不自动移动旧输入节点或发布全部候选；输入输出区初始为空，允许逐步整理。
2. 旧图的直接上传与连线继续兼容，新快照适配节点不与 referenceImages/referenceMedia 存储合同混淆，不重复回灌图片。
3. 验证 Run 提交冻结本地资产、文本与快照来源；输入更新时正在执行 Run 和旧候选不变。
4. 文件/事务故障注入、孤立文件回收、读取 pin 释放、Checkpoint/删除/批准保护回归。
5. 人工 UI 与无浏览器 Agent API 完成同一业务场景；同步文档和 Skill。

端到端产品样例：项目 A 新建人物画布 → 发布文字和图片 → 项目 B 镜头画布引入 → 连接并生成 → 上游发布新版 → 下游保持旧输入 → 预览并更新 → 旧 Run 保持旧来源 → 回退输入 → 移出/加入项目 → 删除来源后仍使用快照。本次真实服务验收覆盖素材流通与成果，Run 冻结使用服务集成测试；未提交额外 Provider 生成。

每阶段完成相关行为测试、后端 TypeScript 编译、前端生产构建。改后端按 AGENTS.md 重启 3100，验证 `/api/health` 与新增路由；UI 验收使用 8000，必要时可重启。文档阶段状态必须附真实证据，不以接口存在标记完成。

## 13. 风险与实施控制

| 风险 | 处理方式 |
|---|---|
| 视频与版本副本占用增加 | 显示组大小/画布占用，完整历史第一版保留；去重与清理另行设计 |
| 大文件复制导致 lease 到期 | 前端/Agent 持续正常续租，提交前再校验；交接时停止新任务并安全排空或放弃未提交暂存 |
| 来源变化或删除与复制竞争 | 固定 manifest + 临时文件 pin + 全组成功才提交 |
| 输入更新破坏连线或稳定提示词引用 | 稳定 itemKey 与类型校验，提交前返回受影响使用点 |
| 新功能绕过既有 AI 控制合同 | 所有写操作进入共享命令服务、Registry、revision/lease/log |
| 旧画布或恢复点缺少 IO 字段 | 显式 schema 兼容，不自动重排旧图，不回退项目归属 |

实施前再次核对工作区已有改动，保护其他任务的未提交内容。每阶段单独记录实际范围、测试证据、迁移结果、已知限制和变更；本文件维护 P1–P4，AI-NATIVE-CANVAS.md 记录与控制面相关的交叉变更。
